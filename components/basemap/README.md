# basemap

The background map every map on the platform draws on, from the cluster itself (T-4638): no
Google, no Mapbox, no key, no fee per view, and a visitor's browser asks no other host.

- **The tiles.** One [PMTiles](https://docs.protomaps.com/pmtiles/) file of the regions in
  `default-environment.yaml.gotmpl`, extracted from the newest
  [Protomaps daily build](https://build.protomaps.com) by `pmtiles extract --region`, which
  reads only the byte ranges it needs. Slovakia, Czechia and Finland at zoom 15 measured
  5.0 GB on the 2026-10-17 build.
- **The style.** `charts/tiles/files/styles/light-<lang>.json`, the Protomaps light flavour
  with labels in sk, en, cs or fi (the place's own name where OpenStreetMap has no
  translation), generated by `scripts/basemap-style.mjs`. Every URL in it is on this host;
  the only foreign addresses are the two attribution links.
- **Fonts and sprites.** `protomaps/basemaps-assets` at the pinned commit, fetched once per
  commit by the refresh job.
- **The server.** nginx, read-only, on `https://tiles.{domain}/`: range requests (206),
  `Cache-Control: public, max-age=86400`, CORS for the installation's own hosts, `GET`,
  `HEAD` and the preflight only.

A page draws it with MapLibre and the `pmtiles` protocol:
`https://tiles.{domain}/styles/light-sk.json`.

## Refresh

A CronJob on the 1st of the month at 03:00 UTC (`charts/tiles/files/refresh.sh`). It checks the
pmtiles release against its sha256, takes the newest build of the last eight days, prints the
volume's `df` line, and refuses to start when the expected size plus 20 % does not fit, so the
old file stays. It writes a temporary file, verifies it and renames it over the old one, so the
server never reads half a file. `dev-smoke` fails when the file is older than 40 days.

A fresh volume has no file: run the first extract by hand once after the first apply.

```sh
kubectl -n <namespace> create job --from=cronjob/basemap-tiles basemap-tiles-first
```
