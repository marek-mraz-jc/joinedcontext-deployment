# Secrets

Two kinds of credential live in a joinedcontext instance, and they are handled differently.

## 1. Bootstrap secrets — generated in the cluster

Passwords no human ever needs to know (the Keycloak admin password, database passwords,
the APISIX OIDC session key, Keycloak client secrets) are generated by
`charts/secrets-generator` on first install and never leave the cluster. A component
declares what it needs in its own `secrets.yaml`:

```yaml
keycloak:
  app:
    db-keycloak:
      username: 'keycloak'          # a literal: used as written
      password:
        length: 32                  # generated, 32 characters minimum
        generate: true
      componentNamespaces:          # every namespace that gets a copy
        - keycloak
        - postgres
```

`defaults/environment/secrets.yaml.gotmpl` collects these into `managedSecrets` and also
derives one `keycloak-client-<id>` secret per confidential client in a component's
`keycloak-clients.yaml`.

Two properties matter:

- **Idempotent.** The chart looks the Secret up in each target namespace first and reuses
  the value it finds, so a re-apply never rotates a live credential.
- **Survives an uninstall.** Every generated Secret carries
  `helm.sh/resource-policy: keep`.

`scripts/check-secrets.py rendered.yaml` verifies both on a rendered manifest and fails if
any declared length drops below 32 characters. CI runs it on every environment.

## 2. Operator-supplied secrets — SOPS + age

A credential that comes from outside (an SMTP password, an S3 key, a department's MQTT
login) is never generated and must never be committed in plaintext (CC-06, ADR-N-012).
Encrypt it with `age` and reference it from the environment; helmfile resolves the
reference itself through `vals`, so the plaintext only ever exists in memory during a
template or apply, and no Helm plugin is involved.

```bash
age-keygen -o .secrets/age-dev.key                 # keep out of Git, mode 600
recipient=$(age-keygen -y .secrets/age-dev.key)
sops --encrypt --age "$recipient" plain.yaml > deployment/environments/dev/secrets.enc.yaml
```

Then point at a value by path instead of pasting it:

```yaml
managedSecrets:
  - keycloak:
      app:
        keycloak-smtp:
          password: ref+sops://environments/dev/secrets.enc.yaml#/smtp/password
          componentNamespaces: [keycloak]
```

`SOPS_AGE_KEY_FILE=.secrets/age-dev.key` (or `SOPS_AGE_KEY`) has to be in the environment
of whoever runs `helmfile`; in CI it is a workflow secret. `tests/test_secrets.py` runs the
whole round trip — encrypt, reference, render — so the wiring stays proven.

The encrypted file belongs in the deployment repository next to the environment it serves.
Multi-cluster and multi-tenant installations use OpenBao instead; see ADR-N-012.
